# foefie 0.2.0

Draft release notes. Not tagged or published.

foefie 0.2.0 moves the command list out of the code and into a config file, adds a wizard for starting new projects, and hardens `foefie test`. Parent issue: #7.

## Highlights

- **Config-driven commands (#10).** Projects and commands now come from `foefie.toml` in the workspace root. Errors name the file and the key. Set `FOEFIE_CONFIG` to use another path. Without a file, foefie falls back to the bundled `foefie.example.toml`, which holds all 16 v0.1 commands. The hard-coded definitions are gone from `cli.py`.
- **`foefie new` (#11).** The wizard asks for the org, name, type, Python version, build backend and author, then runs `uv init`, lists the folder in `dev.code-workspace` and the README, and can create a private GitHub repo (it never pushes). It also appends the project to `foefie.toml`, creating the file from the bundled example if missing. Existing entries are never changed.
- **Runner fix (#9).** `foefie test` runs every suite even when one project directory or tool is missing, and exits with the first failure. Exit codes are 2 for a missing directory, 127 for a missing tool, and the subprocess status otherwise.
- **Internal split (#8).** The CLI is now `workspace`, `runner` and `cli` modules. Python 3.12 or newer is required. Tooling: pytest, ruff, towncrier and mise `test`, `lint` and `ci` tasks. Behaviour is unchanged.

## Upgrading

- Python 3.12 or newer is now required.
- Nothing to migrate. With no `foefie.toml`, the bundled example gives the same commands as 0.1.0. Copy the bundled `foefie.example.toml` (in `src/foefie/`) to `foefie.toml` in the workspace root to customise.

## Decisions

- ADR 0001: record decisions as ADRs
- ADR 0002: config-driven commands
- ADR 0003: no launchd, foefie is a CLI and not a service
